# วิเคราะห์ Flow ระบบ "ภารกิจโดเมนของร้านฉัน"

อ้างอิงจากภาพ 3 ภาพ: กรอบแนวคิดระบบ, Flow การทำงาน 5 สถานี, Workflow swimlane รายนาที
บันทึกเมื่อ 29 กันยายน 2569

---

## 1. ระบบนี้คืออะไร

เกม/สื่อการสอนแบบ Personalized Learning ใช้ AI ช่วยจัดเส้นทาง สำหรับวิชา **อินเทอร์เน็ตในงานธุรกิจดิจิทัล ระดับ ปวช.1**
โจทย์ของผู้เรียนคือ **ตั้งชื่อโดเมนและเลือกนามสกุลโดเมนให้ร้านของตัวเอง** แล้วทดสอบกับลูกค้า

ใช้อุปมา "สร้างร้าน" ตลอดเกม: ที่ดินให้เช่า → ฐานราก → ก่ออิฐ → ติดป้ายร้าน + ใบจดทะเบียน → Grand Opening
ทุกขั้นมีกุญแจล็อก ต้องผ่านเกณฑ์จึงไปต่อ

## 2. โครงสร้าง 3 ชั้น (จากภาพกรอบแนวคิด)

| ชั้น | องค์ประกอบ |
|---|---|
| **Input** | ข้อมูลผู้เรียน (ความรู้เดิม ความสนใจ เป้าหมาย ความมั่นใจ) / แม่แบบของครู 6 แบบ + เกณฑ์รูบริก / หลักการ Personalized Learning |
| **Process** | 1 โปรไฟล์ผู้เรียน → 2 AI จัดเส้นทาง (ระดับตัวช่วย + สถานการณ์เฉพาะคน) → 3 ภารกิจ 5 สถานี → 4 ประเมินและสะท้อนผล **โดยมีห้องสมุดทบทวนเปิดได้ตลอดเวลา** |
| **Output** | ผู้เรียนเลือกโดเมนให้ธุรกิจได้ / กำกับการเรียนรู้ตนเองได้ / ครูได้ข้อมูลรายคนไปพัฒนาการสอน |

มี feedback loop กลับไปปรับสื่อ แม่แบบ และโปรไฟล์ — คาบถัดไปเริ่มจากโปรไฟล์ล่าสุด

## 3. ไทม์ไลน์ 1 คาบ (60 นาที) แยกตามผู้เกี่ยวข้อง

| ช่วง | นักเรียน | ระบบ/AI | ครู |
|---|---|---|---|
| ก่อนคาบ | — | — | ตั้งค่าห้องเรียน สร้างรหัสห้อง เลือกโหมดเต็ม/สั้น ตั้งเวลาแต่ละช่วง ล็อกสถานี |
| 0–5 | สแกน QR ใส่รหัสห้อง ชื่อเล่น รหัส 4 หลัก → ดูวิธีเล่น 1 นาที → กรอก "ธุรกิจของฉัน" → ตอบก่อนเรียน 4 ข้อ + ระดับความมั่นใจ → ตั้งเป้าหมายวันนี้ | สร้างโปรไฟล์ผู้เรียน บันทึกผลก่อนเรียน → ตรวจคำตอบรายจุดประสงค์ → จัดระดับตัวช่วย 1/2/3 | ดูแผงความพร้อมของทั้งห้อง |
| 5–25 | ภารกิจถูกล็อก ฟังครูสอน | AI เลือกแม่แบบ T1–T6 แล้วเติมเรื่องร้านของผู้เรียนเข้าไป | สอนสไลด์ จุดประสงค์ 1–4 ยกภารกิจนักเรียนเป็นตัวอย่าง เน้นเรื่องที่ห้องยังไม่รู้ |
| 25–28 | ตอบหลังเรียน 4 ข้อ → เห็น "เส้นทางของฉัน" พร้อมเหตุผลจาก AI (ขอเปลี่ยนระดับได้) | — | ปลดล็อกภารกิจทั้งห้อง |
| 28–48 | **สถานี A** โรงทำป้าย ตั้งชื่อโดเมน → **สถานี B** สำนักงานจดทะเบียน เลือกนามสกุล (.com .co.th .in.th .shop .ไทย) → **สถานี C** ลานทดสอบลูกค้า (เพื่อน / ส่งลิงก์ / ลูกค้าจำลอง AI) | ด่านตรวจ 4 จุด: ผ่านกฎครบ 4 ข้อ? / นามสกุลตรงเรื่องร้าน? / ผู้ทดสอบเข้าใจถูกอย่างน้อย 1 ใน 2? / ถูกอย่างน้อย 3 ใน 4? ไม่ผ่าน → AI ถามนำ, ถามกลับ, ให้กลับไปปรับชื่อ, หรือส่งไปทบทวนในห้องสมุด | แผงห้องเรียนสด (เขียว/เหลือง/แดง) จัดกลุ่มสอนเสริมตามจุดอ่อน จับคู่พี่เลี้ยง ขยายเวลา |

> ใบประกาศออกให้เมื่อ **ครูยืนยันคะแนนแล้วและได้ระดับ 3 ขึ้นไปครบทั้ง 4 ด้าน** ไม่ผูกกับดาว · คนที่ยังไม่ครบเห็นว่าเหลือด้านไหน ต้องเพิ่มอะไร แล้วแก้ส่งใหม่ได้ (กติกาเต็มที่ `personalized-learning-design.md` ข้อ 5.13)
| 55–60 และหลังคาบ | สะท้อนคิด 3 คำถาม (ได้เรียนรู้อะไร / ยังสงสัยอะไร / จะนำไปใช้อย่างไร) → ตั้งเป้าครั้งหน้า → เล่นต่อที่บ้านได้ถึงวันที่ครูกำหนด | อัปเดตโปรไฟล์ผู้เรียน → รวมข้อสงสัยของทั้งห้อง | รายงานรายคน/รายห้อง ก่อน-หลังเรียน → ปรับสไลด์ แม่แบบ กลุ่มสอนเสริม |

## 4. จุดแข็งของ flow นี้

1. **ตรงเกณฑ์ให้คะแนนของอาจารย์** — เข้าเงื่อนไข "Personalized Education" และ "ระบบนิเวศการเรียนรู้" พร้อมกัน ไม่ใช่แค่เกมลอย ๆ
2. **ครูอยู่ในระบบจริง** ไม่ใช่แค่ผู้ดูผล — ตั้งค่าคาบ ปลดล็อกสถานี ยืนยันคะแนน ปรับสไลด์จากข้อมูลจริง นี่คือจุดที่งานส่วนใหญ่ไม่มี
3. **วัดผลได้** มีก่อนเรียน 4 ข้อ / หลังเรียน 4 ข้อ / รูบริก / ความมั่นใจ ทำให้ตอนนำเสนอมีตัวเลขโชว์ ไม่ใช่แค่ความเห็น
4. **เข้าระบบง่าย** ชื่อเล่น + รหัส 4 หลัก ไม่ต้องสมัคร ไม่เก็บข้อมูลส่วนบุคคล เป็นผลดีทั้งด้านเวลาในคาบและด้าน PDPA
5. **มีทางออกเมื่อทำไม่ทัน** งานค้างถูกบันทึกไว้ทำต่อนอกคาบ ทั้งห้องยังได้ไปเวทีเปิดร้านพร้อมกัน ไม่มีใครถูกทิ้ง
6. **AI ไม่ตัดสินคนเดียว** ครูยืนยันคะแนนเสมอ ลดความเสี่ยงที่ AI ให้คะแนนงานภาษาไทยผิด

## 5. ปัญหาและความเสี่ยงที่ต้องแก้ก่อนลงมือ

### 5.1 ขอบเขตเนื้อหาแคบลงมาก
Flow ใหม่โฟกัสเรื่อง **ชื่อโดเมนและนามสกุลโดเมน** ซึ่งตรงกับหน่วยที่ 1 หัวข้อ 1.4 (ชื่อโดเมนและระบบ DNS) เท่านั้น
เอกสารเนื้อหา 39 หน้าที่ทำไว้ครอบ 6 หน่วยทั้งวิชา → ใช้ได้จริงกับ flow นี้ประมาณ 2 หน้า

**ต้องตัดสินใจ:** จะทำสื่อ 1 คาบเรื่องโดเมน (ลึก เสร็จทัน) หรือขยายให้ครบ 6 หน่วย (กว้าง เสี่ยงไม่ทัน)
ถ้าเลือกอย่างแรก เอกสารเนื้อหาต้องเขียนใหม่ให้ลึกเฉพาะเรื่องโดเมน: หลักการตั้งชื่อ, การเลือกนามสกุล, การจดทะเบียน, ค่าใช้จ่าย, กรณีชื่อชนเครื่องหมายการค้า

### 5.2 เกณฑ์ผ่านยังไม่ชัด
ในภาพเขียนแค่ "ผ่านกฎครบ 4 ข้อ?" แต่ไม่ได้ระบุว่า 4 ข้อคืออะไร ต้องนิยามให้ตรวจด้วยโปรแกรมได้ ตัวอย่างที่ใช้ได้จริง:

| กฎ | เงื่อนไขที่ตรวจได้ |
|---|---|
| 1 | ความยาว 3–20 ตัวอักษร |
| 2 | ใช้ได้เฉพาะ a-z, 0-9 และขีดกลาง ห้ามขีดกลางนำหน้าหรือปิดท้าย |
| 3 | สะกดแล้วอ่านออกเสียงตามได้ ไม่มีตัวอักษรซ้ำติดกันเกิน 2 ตัว |
| 4 | สื่อถึงประเภทธุรกิจที่ผู้เรียนกรอกไว้ (ตรวจด้วยคำสำคัญ หรือให้ AI ตัดสินแล้วครูยืนยัน) |

กฎข้อ 1–3 เขียนเป็นฟังก์ชันตรวจได้ทันทีโดยไม่ต้องใช้ AI — ควรทำแบบนั้น เร็วกว่าและไม่มีค่าใช้จ่าย

### 5.3 การเช็กว่าโดเมนว่างหรือไม่
ถ้าจะให้สมจริงต้องต่อ API ตรวจโดเมน (RDAP/WHOIS) ซึ่งมีปัญหา 3 อย่างในห้องเรียน: ช้า, บางครั้งล่ม, โดเมน `.ไทย` และ `.co.th` มีเงื่อนไขพิเศษ
**แนะนำ:** ใช้ชุดข้อมูลจำลองที่เตรียมไว้ล่วงหน้า (รายชื่อโดเมนที่ "ถูกจองแล้ว" ประมาณ 200 ชื่อ) ให้ผลทันทีและคุมบทเรียนได้ ส่วนการเช็กจริงทำเป็นปุ่มเสริมที่พังได้โดยไม่กระทบเกม

### 5.4 ภาระการเขียนเนื้อหา
แม่แบบ T1–T6 × ระดับตัวช่วย 3 ระดับ = ต้องเขียนบท **18 ชุด** ยังไม่รวมคำถามก่อน/หลังเรียน คำถามนำของ AI และเนื้อหาห้องสมุด
นี่คืองานที่กินเวลามากที่สุด มากกว่างานเขียนโค้ด — ต้องเริ่มเขียนคู่ขนานไปกับการพัฒนา ไม่ใช่รอทำทีหลัง

### 5.5 ต้นทุนและความเสถียรของ AI
- ใครออกค่า API ตอนนำเสนอและตอนใช้จริงในห้อง 20–40 คน
- เน็ตโรงเรียนช้า/หลุด ระบบต้องทำงานต่อได้ → **ทุกจุดที่ใช้ AI ต้องมีทางสำรองแบบกฎ (rule-based)** ถ้า AI ไม่ตอบใน 5 วินาที ให้ใช้คำใบ้สำเร็จรูปแทน
- "ลูกค้าจำลอง AI" ในสถานี C เป็นช่องที่นักเรียนพิมพ์อะไรก็ได้ ต้องกันการถามนอกเรื่องและคำหยาบ

### 5.6 แผงห้องเรียนสด
ต้องมี backend ที่อัปเดตสถานะนักเรียน 20–40 คนแบบเกือบทันที — นี่คือส่วนที่หนักที่สุดทางเทคนิคของทั้งระบบ
ถ้าเวลาไม่พอ ให้ลดเป็น polling ทุก 3–5 วินาที ซึ่งเพียงพอกับการใช้งานจริงและง่ายกว่า realtime มาก

### 5.7 เวลาในคาบตึง
ช่วง 28–48 = 20 นาที ต้องผ่าน 3 สถานี เฉลี่ยสถานีละไม่ถึง 7 นาที รวมเวลาที่ AI ตอบและการแก้งานเมื่อไม่ผ่าน
ควรทดลองจับเวลาจริงก่อน แล้วเตรียม "โหมดสั้น" ที่ตัดสถานี C ออก (ในภาพมีโหมดเต็ม/สั้นอยู่แล้ว — ต้องนิยามให้ชัดว่าโหมดสั้นตัดอะไร)

### 5.8 รหัส 4 หลักกับการชนกัน
ชื่อเล่นซ้ำกันได้ในห้องเดียว และรหัส 4 หลักเดาง่าย นักเรียนอาจเข้าบัญชีเพื่อนได้
แก้ด้วยการผูก key ไว้ในเครื่อง (localStorage) และให้รหัส 4 หลักใช้เฉพาะตอนย้ายเครื่อง

## 6. ข้อเสนอขอบเขตขั้นต่ำ สำหรับส่ง 80% วันที่ 7 ตุลาคม 2569

ทำให้ครบเส้นทาง แต่ตัดของที่ยังไม่จำเป็นออก

**ทำ**
- เข้าระบบด้วยรหัสห้อง + ชื่อเล่น
- แบบสอบถามก่อนเรียน 4 ข้อ + ความมั่นใจ → สร้างโปรไฟล์
- จัดระดับตัวช่วย 1/2/3 ด้วย**กฎ** ก่อน (คะแนนก่อนเรียน + ความมั่นใจ) ยังไม่ต้องใช้ AI
- สถานี A ตั้งชื่อโดเมน + ตรวจกฎ 4 ข้อด้วยโปรแกรม
- สถานี B เลือกนามสกุลโดเมน + อธิบายเหตุผลว่าทำไมนามสกุลนั้นเหมาะกับร้าน
- หน้าสรุปผล + ใบประกาศเปิดร้าน (สร้าง PDF ในเบราว์เซอร์แบบเดียวกับ Interland)
- แผงครูแบบอ่านอย่างเดียว เห็นว่าใครถึงสถานีไหน (polling)

**ยังไม่ทำในรอบนี้**
- สถานี C ลูกค้าจำลอง AI
- การประเมินข้อความยาวด้วย AI
- แม่แบบ T1–T6 ครบทั้ง 6 แบบ (ทำ 2 แบบก่อน)
- การเช็กโดเมนว่างจริงผ่าน API

เหตุผล: ส่วนที่ตัดออกทั้งหมดขึ้นกับ AI และ backend ซึ่งเป็นจุดที่พังง่ายที่สุดตอนสาธิตหน้าห้อง ส่วนที่เหลือเดโมได้จริงและครบเรื่อง

## 7. Stack ที่เหมาะกับ flow นี้

flow นี้ไม่ใช่เกม 3D แต่เป็น **เว็บแอปหลายผู้ใช้ที่มีแดชบอร์ดครู** ดังนั้นคนละโจทย์กับ Interland

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| Frontend | Next.js + TypeScript + Tailwind | ทำหน้าเว็บกับหน้าครูในโปรเจกต์เดียว เขียน API route ได้เลย |
| ฐานข้อมูล + realtime | Supabase (Postgres) | มี realtime และ row level security มาให้ ไม่ต้องเขียน server เอง |
| AI | Claude API เรียกผ่าน API route ฝั่งเซิร์ฟเวอร์ | ห้ามวาง API key ไว้ฝั่งเบราว์เซอร์เด็ดขาด |
| ภาพ/อนิเมชัน | ภาพ 2D + Framer Motion หรือ Lottie | ไม่ต้องใช้ 3D เลย ได้ภาพสวยเร็วกว่ามาก |
| ใบประกาศ | jsPDF ในเบราว์เซอร์ | ไม่ต้องใช้ server |

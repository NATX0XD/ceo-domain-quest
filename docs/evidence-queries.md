## 0. รันยังไง

**เงื่อนไขก่อนรัน** Supabase local ต้องขึ้นอยู่ (`supabase start`) และต้องมีข้อมูลของคาบที่จะเอาไปโชว์อยู่ในฐานข้อมูลแล้ว

**วิธีที่สั้นที่สุด — ยิงทีละ query ผ่าน docker exec** (copy ไปวางได้เลย เปลี่ยนแค่รหัสห้อง)

```bash
docker exec supabase_db_digital-biz-quest psql -U postgres -d postgres -q -c "
select count(*) as นักเรียนทั้งห้อง
from students s join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9';"
```

**วิธีที่เร็วกว่าเมื่อจะรันทั้งชุด — เก็บเป็นไฟล์แล้วยิงทีเดียว**

```bash
# 1) สร้างไฟล์ evidence.sql แล้ววาง query ทั้งหมดจากหัวข้อ 1-13 ลงไป
#    บรรทัดแรกของไฟล์ตั้งรหัสห้องไว้ตัวเดียว ทุก query ข้างล่างจะใช้ค่านี้
#       \set room 'QUEST9'
#    แล้วในแต่ละ query อ้างด้วย  :'room'
# 2) ยิงทั้งไฟล์
docker exec -i supabase_db_digital-biz-quest psql -U postgres -d postgres -q < evidence.sql
```

**เปิดดูด้วยตาแทนได้** Supabase Studio ที่ `http://localhost:54323` → SQL Editor → วาง query แล้วกด Run
เหมาะกว่าตอนซ้อมพูด เพราะผลออกมาเป็นตารางอ่านง่ายและ screenshot ไปใส่สไลด์ได้เลย

**ข้อควรระวัง 3 ข้อ**
1. ชื่อคอนเทนเนอร์ `supabase_db_digital-biz-quest` ผูกกับชื่อโปรเจกต์ ถ้าเครื่องใครไม่ตรงให้เช็กด้วย `docker ps --format '{{.Names}}' | grep supabase_db`
2. ชื่อคอลัมน์ผลลัพธ์ภาษาไทยยาวเกิน 63 ไบต์ psql จะตัดให้พร้อมขึ้น NOTICE — **ไม่ใช่ error** แต่ในไฟล์นี้ตั้งชื่อให้สั้นพอแล้วทุกอัน
3. query ทั้งหมดเป็น **read-only** ไม่มี insert/update/delete ยิงซ้ำกี่รอบก็ได้ ไม่กระทบข้อมูลคาบจริง

## 2. ตัว query

### Q0 · จำนวนนักเรียนในห้อง

```sql
select count(*) as นักเรียนทั้งห้อง
from students s
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9';
```

### Q1 · ระบบเสนอช่องทางไหนกี่คน

```sql
select coalesce(p.channel_suggested, '(ยังไม่ได้เสนอ)') as ระบบเสนอ,
       count(*) as คน
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
group by 1
order by 2 desc;
```

### Q2 · ผู้เรียนใช้ช่องทางไหนจริง

```sql
select coalesce(p.learning_route, '(ยังไม่ได้เลือก)') as เลือกจริง,
       count(*) as คน
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
group by 1
order by 2 desc;
```

### Q3 · กี่คนไม่เอาตามที่ระบบเสนอ ← ตัวเลขสำคัญที่สุดของสไลด์

```sql
select count(*) filter (where p.learning_route is distinct from p.channel_suggested) as ไม่เอาตามเสนอ,
       count(*) filter (where p.learning_route = p.channel_suggested)                as เอาตามเสนอ,
       count(*)                                                                      as ตอบครบแล้ว
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and p.channel_suggested is not null
  and p.learning_route is not null;
```

### Q4 · ใครเป็นคนเลือก

```sql
select coalesce(p.channel_chosen_by, '(ยังไม่ได้กด)') as คนเลือก,
       count(*) as คน
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
group by 1
order by 2 desc;
```

> `system` = กดยืนยันตามที่ระบบเสนอ · `student` = เลือกเส้นทางอื่นเอง **ทั้งสองค่าคือการตัดสินใจของผู้เรียนทั้งคู่** ต่างกันแค่ว่าตรงกับข้อเสนอหรือไม่ อย่าพูดว่า `system` แปลว่าระบบบังคับ

### Q5 · เปลี่ยนเส้นทางกลางคาบ กี่ครั้ง กี่คน

```sql
select count(*)                      as ครั้ง,
       count(distinct r.student_id)  as คน
from route_changes r
join students s on s.id = r.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and r.from_route is not null;
```

> `from_route is null` คือแถวแรกตอนระบบตั้งค่าให้ ไม่ใช่การเปลี่ยนใจ **ต้องกรองออกเสมอ** ไม่งั้นตัวเลขจะพองเกินจริง

### Q6 · เปลี่ยนตอนภารกิจไหนมากที่สุด

```sql
select coalesce(r.mission_id, '(นอกภารกิจ)') as ภารกิจ,
       count(*) as ครั้ง
from route_changes r
join students s on s.id = r.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and r.from_route is not null
group by 1
order by 2 desc;
```

### Q7 · เปลี่ยนตอนนาทีที่เท่าไรของคาบ

```sql
select floor(extract(epoch from (r.changed_at - c.opens_at)) / 60)::int as นาทีที่,
       count(*) as ครั้ง
from route_changes r
join students s on s.id = r.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and r.from_route is not null
group by 1
order by 1;
```

> นับจาก `classrooms.opens_at` ซึ่งคือเวลาที่ครูเปิดห้อง ไม่ใช่เวลาที่เด็กเข้ามา

### Q8 · เปลี่ยนจากสายไหนไปสายไหน

```sql
select r.from_route as จากสาย,
       r.to_route   as ไปสาย,
       count(*)     as ครั้ง
from route_changes r
join students s on s.id = r.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and r.from_route is not null
group by 1, 2
order by 3 desc;
```

### Q9 · กี่คนยกเป้าหมายตัวเองขึ้น

```sql
select count(*) filter (where p.goal_raised_at is not null) as ยกเป้ากี่คน,
       coalesce(sum(p.goal_raised_count), 0)                as ยกกี่ครั้ง,
       count(*)                                             as ตั้งเป้าแล้วกี่คน
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and p.goal_id is not null;
```

### Q10 · ยกเป้าตอนนาทีที่เท่าไร ใครบ้าง

```sql
select s.nickname    as ชื่อเล่น,
       p.goal_id     as เป้าปัจจุบัน,
       p.goal_stars  as ดาวเป้า,
       floor(extract(epoch from (p.goal_raised_at - c.opens_at)) / 60)::int as ยกตอนนาทีที่
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
  and p.goal_raised_at is not null
order by 4;
```

### Q11 · กี่คนกดปรับระดับตัวช่วยเอง

```sql
select count(*) filter (where jsonb_array_length(p.level_overridden_by_student) > 0) as ปรับเองกี่คน,
       coalesce(sum(jsonb_array_length(p.level_overridden_by_student)), 0)           as ปรับกี่ครั้ง
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9';
```

### Q12 · ดาวที่ได้เทียบกับเป้าที่ตั้งเอง

```sql
select case
         when p.goal_stars is null          then '(ยังไม่ตั้งเป้า)'
         when p.earned_stars < p.goal_stars then 'ต่ำกว่าเป้า'
         when p.earned_stars = p.goal_stars then 'ตรงเป้า'
         else                                    'เกินเป้า'
       end      as ผล,
       count(*) as คน
from profiles p
join students s on s.id = p.student_id
join classrooms c on c.id = s.classroom_id
where c.room_code = 'QUEST9'
group by 1
order by 2 desc;
```

> ผลตรงนี้ตรงกับ `goalOutcome()` ใน `core/personalize.ts` ที่คืน `below | met | exceeded` และตรงกับการ์ด `compare-below / compare-met / compare-exceeded` ใน `content/reflection.json`

### Q13 · ระบบเคยลดเป้าให้ใครไหม

```sql
select proname                              as ฟังก์ชัน,
       (prosrc like '%ห้ามลดเป้าหมาย%')      as กันลดเป้าไว้ในตัวฟังก์ชัน
from pg_proc
where proname = 'set_self_goal';
```

> ตอบด้วยตัวฟังก์ชันในฐานข้อมูลเลย ไม่ต้องนับแถว — `set_self_goal` โยน error ทันทีถ้าเป้าใหม่ต่ำกว่าเป้าเดิม
> ถ้ากรรมการอยากเห็นโค้ดจริง เปิด `supabase/migrations/20260929120000_personalized_learning.sql` บรรทัด 193 (ตัวโยน error อยู่บรรทัด 212) ให้ดู

### Q14 · คิวตรวจงานด้วย AI เดินครบไหม ← คู่กับสไลด์ 6 ชั้น ก

```sql
select status                                        as สถานะคิว,
       count(*)                                      as จำนวนงาน,
       round(avg(attempts), 2)                       as ลองเฉลี่ย
from grade_jobs
group by 1
order by 2 desc;
```

> ใช้ตอบคำถามกรรมการข้อ 28 (ทำไมไม่ให้ AI ตรวจสด) ด้วยของจริงในฐานข้อมูล ไม่ใช่แค่เล่าผลสคริปต์
> อ่านผลแบบนี้: `done` คืองานที่ AI ตรวจเสร็จแล้ว · `pending` คือยังไม่ถึงคิว · `failed` คือลองครบ 3 ครั้งแล้วไม่สำเร็จ **ซึ่งไม่กระทบดาวของนักเรียน** เพราะดาวมาจากกฎไปตั้งแต่ตอนกดส่ง
> ⚠️ ถ้าเห็น `pending` ค้างเยอะ แปลว่ายังไม่มีใครสั่งให้คิวเดิน — ให้ครูกดปุ่มตรวจทั้งห้อง หรือยิง `POST /api/jobs/drain` **ก่อนขึ้นเวที** ไม่ใช่ระหว่างนำเสนอ

## 3. ถ้าตัวเลขออกมาไม่สวยจะพูดยังไง

> **กฎเหล็กข้อเดียว: ห้ามแต่งตัวเลข ห้ามเลือกโชว์เฉพาะ query ที่ผลสวย**
> ถ้ากรรมการจับได้ว่าตัวเลขบนสไลด์ไม่ตรงกับฐานข้อมูล จบทั้งงาน ไม่ใช่แค่หัวข้อเดียว
> ตัวเลขที่ไม่สวยแต่จริง ยังได้คะแนน "รู้ข้อจำกัดตัวเอง" — ตัวเลขสวยแต่ปลอม ได้ 0

| สถานการณ์ | พูดว่าอย่างนี้ | **ห้ามพูด** |
|---|---|---|
| **Q3 = 0** ไม่มีใครเปลี่ยนใจจากที่ระบบเสนอเลย | "ในกลุ่มนี้ทุกคนเห็นด้วยกับเส้นทางที่ระบบเสนอ สิทธิ์ปฏิเสธมีอยู่จริงและกดได้ตลอด แต่ยังไม่ถูกใช้ในกลุ่มนี้ — ซึ่งก็เป็นข้อมูลที่บอกเราว่าตัวแนะนำทำงานได้ตรงพอสมควร สิ่งที่เรายังพิสูจน์ไม่ได้คือถ้าแนะนำผิด เด็กจะกล้าเปลี่ยนไหม ต้องทดลองกับกลุ่มใหญ่กว่านี้" | "เด็กชอบที่ระบบเลือกให้" (เดาใจ) · ข้ามสไลด์นี้ไปเงียบ ๆ |
| **Q5 = 0** ไม่มีใครสลับเส้นทางกลางคาบ | "ไม่มีใครสลับกลางคาบในกลุ่มนี้ครับ/ค่ะ ปุ่มอยู่บนสุดของทุกหน้าภารกิจและกดได้ไม่จำกัด เราเลยตีความได้ 2 ทาง — เลือกถูกตั้งแต่แรก หรือยังไม่รู้ว่ากดได้ ข้อหลังเป็นสิ่งที่เราจะไปวัดด้วยการสังเกตในคาบถัดไป" | "ฟีเจอร์นี้ยังไม่เสร็จ" ถ้ามันเสร็จแล้ว · "เด็กคงไม่สนใจ" |
| **Q9 = 0** ไม่มีใครยกเป้าตัวเอง | "ยังไม่มีใครยกเป้าในกลุ่มนี้ เพราะดาวส่วนใหญ่ยังไม่ถึงเป้าเดิม ระบบจะชวนยกเป้าก็ต่อเมื่อทำถึงเป้าที่ตั้งไว้แล้ว ตัวเลขนี้จึงสะท้อนว่าคาบยังไม่จบมากกว่าจะสะท้อนว่าฟีเจอร์ไม่ถูกใช้" (ถ้า Q12 บอกว่าเกินเป้ามีคนแต่ Q9 ยังเป็น 0 **ให้ยอมรับว่าเป็นบั๊ก** อย่าเลี่ยง) | "เด็กไม่มีแรงจูงใจ" · ตัวเลขนี้ไม่สำคัญ |

## 4. ผลรันจริง (ฐานข้อมูล local · ห้อง QUEST9 · 29 กันยายน 2569)

ข้อมูลชุดนี้เป็น **ข้อมูลทดสอบจากสคริปต์ seed 3 คน ไม่ใช่นักเรียนจริง** — แปะไว้เพื่อยืนยันว่า query ทุกตัวรันได้ไม่ error เท่านั้น
ก่อนวันนำเสนอต้องรันซ้ำกับข้อมูลคาบจริงแล้วแทนที่ตัวเลขทั้งหมด

```
== Q0 ==  นักเรียนทั้งห้อง = 3

== Q1 ระบบเสนอ ==        == Q2 เลือกจริง ==
 buddy | 1                buddy | 1
 card  | 1                card  | 1
 clip  | 1                game  | 1

== Q3 ==  ไม่เอาตามเสนอ 1 · เอาตามเสนอ 2 · ตอบครบแล้ว 3
== Q4 ==  system 2 · student 1
== Q5 ==  เปลี่ยนกลางคาบ 1 ครั้ง จาก 1 คน
== Q6 ==  m2 = 1 ครั้ง
== Q7 ==  นาทีที่ 0 = 1 ครั้ง
== Q8 ==  clip -> game = 1 ครั้ง
== Q9 ==  ยกเป้า 0 คน · 0 ครั้ง · ตั้งเป้าแล้ว 3 คน
== Q10 == (0 rows)
== Q11 == ปรับตัวช่วยเอง 0 คน · 0 ครั้ง
== Q12 == ต่ำกว่าเป้า 3 คน
== Q13 == set_self_goal · กันลดเป้าไว้ในตัวฟังก์ชัน = t
```

**รันซ้ำทั้งชุดเมื่อ 30 กันยายน 2569** — query ทั้ง 14 ตัวรันผ่านหมด ไม่มี error สักตัว (ฐานข้อมูลโตขึ้นจากการทดสอบของทีม: `profiles` 51 แถว · `channel_suggested` 15 · `learning_route` 20 · `route_changes` ที่ไม่ใช่แถวแรก 19 · `goal_raised_at` ยังเป็น 0)
ผล **Q14** รอบเดียวกัน: `done 19 งาน · ลองเฉลี่ย 1.05 ครั้ง · ไม่มี failed และไม่มี pending ค้าง` = **คิวตรวจด้วย AI เดินครบทุกงานที่เข้ามา**

**อ่านผลชุดนี้** Q3 ได้ 1 จาก 3 คือมีคนไม่เอาตามที่ระบบเสนอจริง และ Q8 เห็นการย้าย `clip → game` ซึ่งแปลว่าทางเดินของหลักฐานครบวงตั้งแต่ระบบเสนอ → ผู้เรียนเลือก → บันทึกการเปลี่ยนใจ
ส่วน Q9 กับ Q11 เป็น 0 เพราะสคริปต์ seed ยังไม่ได้จำลองการยกเป้าและการกดปรับตัวช่วย **ไม่ใช่เพราะฟีเจอร์ไม่ทำงาน** — ถ้าถึงวันงานยังเป็น 0 ให้ใช้บทพูดในหัวข้อ 3

## 1. โทเคนสี

ตั้งชื่อตาม **ความหมาย** ไม่ใช่ชื่อสี — วันที่ทีมอยากเปลี่ยนเขียวเป็นน้ำเงิน แก้ที่ `globals.css` ที่เดียว ไม่ต้องไล่แก้ทุกหน้า

## 2. สเกลตัวอักษรไทย

ฟอนต์: **Noto Sans Thai** (ผ่าน `next/font/google`, weight 400/500/600/700) — เลือกเพราะเป็นฟอนต์ไทยไม่กี่ตัวที่มี weight ครบและ hinting ดีบนจอมือถือความละเอียดต่ำ

| โทเคน | ขนาด | line-height | ใช้ที่ไหน |
|---|---|---|---|
| `text-hero` | 36px | 1.25 | ตัวเลขคะแนน หน้าฉลอง |
| `text-display` | 30px | 1.35 | หัวหน้าจอ (h1) |
| `text-title` | 24px | 1.45 | หัวส่วน (h2) |
| `text-title-sm` | 21px | 1.50 | หัวการ์ด (h3) |
| `text-body-lg` | 19px | 1.70 | โจทย์ภารกิจ คำถาม |
| **`text-body`** | **17px** | **1.75** | **เนื้อหาหลักทั้งแอป** |
| `text-label` | 15px | 1.60 | ป้ายกำกับ ชิป แท็บ |
| `text-note` | 13px | 1.60 | ข้อความประกอบที่ "ไม่อ่านก็ยังทำภารกิจจบได้" เท่านั้น |

**เหตุผลของตัวเลขเหล่านี้**

- **17px ไม่ใช่ 16px** — ขั้นต่ำที่แนะนำทั่วไปคือ 16px แต่นั่นคิดจากอักษรละติน สระบน (ิ ี ึ ื ่ ้) ของไทยซ้อนเหนือตัวอักษรอีก 2 ชั้น ที่ 16px บนจอ 390px สระกับวรรณยุกต์เริ่มเชื่อมกันเป็นก้อน ขยับเป็น 17px แก้ปัญหาโดยแทบไม่กินพื้นที่เพิ่ม
- **line-height 1.75 สำหรับเนื้อหา** — สูงกว่า 1.5 ที่ใช้กับภาษาอังกฤษ เพราะไทยต้องการที่ว่างให้สระล่าง (ุ ู) ของบรรทัดบนไม่ชนสระบนของบรรทัดล่าง
- **`text-note` 13px ใช้ได้จำกัด** — เล็กกว่านี้อ่านไม่ออกบนมือถือ กติกาคือถ้าข้อมูลนั้นจำเป็นต่อการทำภารกิจ ห้ามใช้ `text-note`
- **ความยาวบรรทัดคุมด้วย `screen-shell` (max 480px)** — ที่ 17px ได้ราว 45–55 ตัวอักษรไทยต่อบรรทัด อยู่ในช่วงที่สายตาไม่หลงบรรทัด แม้บนแท็บเล็ต 820px เนื้อหาก็ยังไม่ยืดจนอ่านยาก

## 3. ระยะห่าง

ฐาน **4px** (`--spacing: 0.25rem`) — ทุกค่าในระบบหารด้วย 4 ลงตัว ไม่มีเลข 5, 7, 13 หลุดมา

| Tailwind | px | ใช้ที่ไหน |
|---|---|---|
| `gap-1` | 4 | ไอคอนกับตัวอักษรในปุ่มเดียวกัน |
| `gap-2` | 8 | ชิปในแถวเดียวกัน |
| `gap-3` | 12 | การ์ดในรายการ |
| `p-4` / `px-4` | 16 | **ขอบซ้ายขวาของทุกหน้าจอ** |
| `p-5` | 20 | ระยะในการ์ด |
| `gap-6` | 24 | ระหว่างบล็อกเนื้อหา |
| `mb-8` | 32 | ระหว่างส่วนใหญ่ของหน้า |
| `mb-10` / `pt-12` | 40 / 48 | หัวหน้าจอกับเนื้อหาแรก |

**ทำไมขอบจอ 16px** — จอ 390px หัก 16px สองข้างเหลือเนื้อหา 358px ถ้าใช้ 24px เหลือ 342px ซึ่งทำให้แถว 3 ชิปเริ่มตัดคำ ส่วน 12px ทำให้เนื้อหาชิดขอบจนนิ้วที่จับขอบมือถือแตะโดนโดยไม่ตั้งใจ

**ระยะเผื่อแถบเมนูล่าง** — ทุกหน้าที่มี `BottomNav` ต้องใส่ `pb-nav` ซึ่งเท่ากับ `--bottom-nav-height + 16px` และ `--bottom-nav-height` = `4.5rem + safe-area-inset-bottom` จึงพ้นทั้งแถบเมนูและแถบ home indicator ของ iPhone

## 5. เงา

ระบบใช้เงา **2 ชั้นซ้อน** (ชั้นใกล้คมนิดหนึ่ง + ชั้นไกลฟุ้ง) และย้อมด้วย `brand-900` แทนสีดำ เงาจึงกลมกลืนกับพื้นครีมแทนที่จะเป็นคราบเทา — นี่คือสิ่งที่ทำให้การ์ดดู "นุ่ม" แบบ claymorphism ใน mockup

| โทเคน | ใช้ที่ไหน |
|---|---|
| `shadow-soft-1` | ชิป ป้าย การ์ดที่ไม่ใช่พระเอก · สถานะ "กดค้าง" ของปุ่ม |
| `shadow-soft-2` | **การ์ดทั่วไปและปุ่มหลัก** |
| `shadow-soft-3` | การ์ดพระเอกของหน้า แถบแจ้งผล |
| `shadow-lift` | ของที่ลอยเหนือทุกอย่าง |
| `shadow-inset-soft` | ช่องที่ควรดูเหมือน "บุ๋มลงไป" |

ฟีดแบ็กตอนกดใช้ `active:translate-y-px` + ลดเงาลงหนึ่งขั้น ให้ความรู้สึกว่าปุ่มถูกกดจมลงจริง — **ไม่ใช้ `scale`** เพราะการย่อขนาดทำให้ของรอบข้างขยับตามในบางเลย์เอาต์

## 6. สถานะปุ่ม

### 6.1 สี่แบบ และเมื่อไรใช้แบบไหน

| แบบ | หน้าตา | ใช้เมื่อ | กติกา |
|---|---|---|---|
| `primary` | ม่วงทึบ + เงา | สิ่งที่อยากให้กดมากที่สุด | **หน้าละ 1 ปุ่มเท่านั้น** ถ้ามี 2 ปุ่มม่วง นักเรียนจะลังเล |
| `secondary` | ม่วงอ่อน ไม่มีเงา | ทางเลือกรองที่ยังอยากให้เห็น เช่น "ดูคำใบ้" | มีได้หลายปุ่มในหน้าเดียว |
| `success` | เขียวทึบ + เงา | ยืนยัน/ส่งคำตอบ (ปุ่ม "ตรวจคำตอบ" ใน mockup) | ใช้เฉพาะตอนส่งของที่ย้อนไม่ได้ |
| `ghost` | โปร่ง ตัวอักษรม่วง | การกระทำที่ถอยออก เช่น "ข้ามภารกิจนี้" | ห้ามใช้เป็นปุ่มหลัก |

### 6.2 ตารางสถานะ

| สถานะ | primary | secondary | success | ghost |
|---|---|---|---|---|
| ปกติ | `bg-brand-600` ขาว | `bg-brand-100` `text-brand-700` | `bg-quest-600` ขาว | โปร่ง `text-brand-700` |
| hover | `bg-brand-700` | `bg-brand-200` | `bg-quest-700` | `bg-brand-50` |
| กดค้าง (active) | `bg-brand-700` + จม 1px + เงาลด | `bg-brand-200` `text-brand-800` + จม 1px | `bg-quest-700` + จม 1px + เงาลด | `bg-brand-100` + จม 1px |
| โฟกัสคีย์บอร์ด | วงแหวน `focus` หนา 3px เว้น 3px | เหมือนกัน | เหมือนกัน | เหมือนกัน |
| ปิดใช้งาน | `opacity-50` + `cursor-not-allowed` + ไม่มีเงา | เหมือนกัน | เหมือนกัน | เหมือนกัน |
| กำลังโหลด | วงหมุน + `aria-busy` + กดซ้ำไม่ได้ + `sr-only` บอกว่ากำลังทำอะไร | เหมือนกัน | เหมือนกัน | เหมือนกัน |

### 6.3 ขนาดกับพื้นที่แตะ

| ขนาด | ความสูงจริง | ใช้เมื่อ |
|---|---|---|
| `sm` | **44px** (`min-h-11`) | ปุ่มในแถวที่มีหลายปุ่ม — ค่านี้คือ **ขั้นต่ำสัมบูรณ์** ของทั้งระบบ |
| `md` | **48px** (`min-h-12`) | ค่าเริ่มต้น |
| `lg` | **56px** (`min-h-14`) | CTA เดียวของหน้า · ปุ่มในแถบเมนูล่าง |

อ้างอิง: WCAG 2.2 เกณฑ์ 2.5.8 (Target Size Minimum) กำหนด 24×24px, Apple HIG กำหนด 44×44pt, Material Design กำหนด 48×48dp — ระบบนี้ยึด **44px เป็นพื้น** และดันขึ้น 48–56px ในจุดที่กดบ่อย เพราะผู้ใช้จริงเป็นวัยรุ่นที่กดเร็วและไม่ค่อยมอง

มี utility `tap-target` (`min-h-11 min-w-11`) สำหรับห่อไอคอนหรือลิงก์ที่หน้าตาเล็กกว่านิ้ว

> **ข้อยกเว้นที่ตั้งใจ:** `StatBadge` ขนาด `sm`/`md` สูง 32/40px ซึ่งต่ำกว่า 44px — ได้เพราะมันเป็น **ป้ายแสดงผล กดไม่ได้** (`<span role="img">`) ไม่ใช่เป้าแตะ ถ้าวันไหนทำให้มันกดได้ ต้องดันเป็น `min-h-11`

### ตรวจซ้ำจาก DOM ที่เรนเดอร์จริง

ตารางข้างบนคือ "คู่สีที่ตั้งใจให้มี" ซึ่งยังไม่พอ เพราะพื้นหลังจริงมักมาจาก element แม่ ไม่ใช่ element เดียวกัน
จึงมีอีกด่านหนึ่ง: ดึง HTML ของ **18 หน้าจากเซิร์ฟเวอร์จริง** แล้วเดินต้นไม้ DOM หา
"สีตัวอักษรที่ใกล้ที่สุด" คู่กับ "สีพื้นที่ใกล้ที่สุด" ของทุก element ที่มีข้อความ

ผลรอบแรก: **31 คู่ ตก 1** — `ink-subtle` บน `surface-sunken` ได้ 4.33
แก้โทเคนแล้วรันซ้ำ: **31 คู่ ผ่านทั้งหมด 0 ตก**

นี่คือเหตุผลที่ต้องตรวจจาก DOM ไม่ใช่ตรวจแค่ตารางโทเคน — คู่ที่ตกไม่ได้ถูกเขียนไว้ใน
className เดียวกันเลย มันเกิดจากลูกที่เป็น `text-ink-subtle` ไปอยู่ในแม่ที่เป็น `bg-surface-sunken`

**คู่สีที่ระบบ "ห้าม" ใช้** (คำนวณแล้วตกเกณฑ์ เก็บไว้กันคนหลงใช้ในอนาคต)

| คู่ | อัตราส่วน | ใช้อะไรแทน |
|---|---|---|
| ขาวบน `spark-500` `#ED7A2D` | 2.82 | ใช้ `spark-600` |
| ขาวบน `reward-500` `#EAB532` | 1.89 | ใช้ `ink` บน `reward-100` หรือใส่ขอบ `reward-700` |
| `reward-500` บนขาว (ดาวไม่มีขอบ) | 1.89 | ต้องมีเส้นขอบ `reward-700` เสมอ |
| `line-strong` `#C2BEDB` บนขาว | 1.79 | ใช้เป็นเส้นตกแต่งได้ แต่ห้ามเป็นขอบที่สื่อความหมาย ใช้ `line-contrast` แทน |

## 8. สิ่งที่ `globals.css` บังคับไว้ให้ทั้งแอป

| สิ่งที่ทำ | ทำไม |
|---|---|
| `@media (prefers-reduced-motion: reduce)` ตัด animation/transition เหลือ 0.01ms | iOS/Android มีสวิตช์ "ลดการเคลื่อนไหว" นักเรียนที่เวียนหัวกับภาพเคลื่อนไหวเปิดไว้จริง ใช้ 0.01ms ไม่ใช่ 0s เพราะ 0s ทำให้ event `transitionend`/`animationend` ไม่ยิงและ logic บางตัวค้าง |
| `--safe-top/right/bottom/left` จาก `env(safe-area-inset-*)` ครบ 4 ด้าน + ใส่เป็น padding ของ `body` | จอบาก iPhone กินพื้นที่บน แถบ home indicator กินพื้นที่ล่าง และตอนหมุนจอแนวนอน "หู" จอกินซ้าย/ขวา มี utility `safe-t` `safe-b` `safe-x` ให้ element ที่ `fixed` ติดขอบจอเรียกใช้ |
| `:focus-visible` ทั่วทั้งเอกสาร → วงแหวน `focus` 3px เว้น 3px | ผ่าน 3:1 บนทุกพื้นหลังในระบบ ใช้ `:focus-visible` ไม่ใช่ `:focus` เพื่อให้วงแหวนขึ้นตอนใช้คีย์บอร์ด/สวิตช์ แต่ไม่ขึ้นค้างตอนแตะนิ้ว |
| `input, textarea, select { font-size: max(1rem, …) }` | iOS Safari ซูมหน้าเข้าอัตโนมัติเมื่อโฟกัสช่องกรอกที่เล็กกว่า 16px แล้วซูมกลับไม่เอง — บั๊กที่นักเรียนเจอบ่อยที่สุด |
| `overflow-x: hidden` ที่ `body` + `img, svg, video, canvas { max-width: 100% }` | กันทุกกรณีที่เนื้อหาดันจอ 390px จนเลื่อนแนวนอน |
| `--z-sticky: 10 / --z-nav: 20 / --z-overlay: 30 / --z-toast: 50` | ประกาศลำดับชั้นไว้ที่เดียว ไม่ให้ใครไล่เดา `z-[9999]` กันเอง |
| `--bottom-nav-height` + utility `pb-nav` | หน้าเนื้อหาเว้นท้ายหน้าได้ถูกต้องโดยไม่ต้องรู้ความสูงจริงของแถบเมนู |

**Utility ที่ใช้ซ้ำบ่อย:** `btn-base` · `btn-quest` · `card-soft` · `card-tap` · `screen-shell` · `pb-nav` · `tap-target` · `focus-ring` · `row-scroll` · `safe-t` / `safe-b` / `safe-x`

## 9. Primitive ใน `components/ui/`

นำเข้าจากจุดเดียว: `import { Button, Card, ProgressBar } from '@/components/ui'`

| Component | props สำคัญ | หมายเหตุด้าน a11y |
|---|---|---|
| `Button` | `variant` (4 แบบ) · `size` · `fullWidth` · `loading` · `leadingIcon` / `trailingIcon` | type บังคับว่า **ปุ่มที่ไม่มีข้อความต้องมี `aria-label`** ไม่งั้น build ไม่ผ่าน · `loading` ตั้ง `aria-busy` + ข้อความ `sr-only` |
| `IconButton` | `icon` · `aria-label` (บังคับ) | ทรงกลม 44/48/56px |
| `Card` · `CardHeader` | `tone` (plain/brand/quest/spark/reward) · `padding` · `elevated` · `as` | `as` เปลี่ยน tag ให้ HTML สื่อความหมายถูก · `CardHeader as` คุมระดับหัวข้อ h2–h4 |
| `StatBadge` | `kind` (star/percent/count) · `value` · `max` · `label` · `hideLabel` | `role="img"` + `aria-label` เป็นประโยคเต็มไทย ("ดาวสะสม 320 ดาว") ไม่ปล่อยให้อ่านเป็น "3 5" |
| `ProgressBar` | `value` · `max` · `label` · `tone` · `size` | `role="progressbar"` ครบ `aria-valuenow/min/max/valuetext` · แสดง % เป็นข้อความคู่กับแถบเสมอ |
| `ChoiceCard` | `label` · `marker` · `selected` · `state` (idle/correct/wrong/locked) | `<button aria-pressed>` · ถูก/ผิดมีไอคอน **และ** ต่อท้าย aria-label ว่า "— ตอบถูก/ตอบผิด" |
| `BottomNav` | `items` · `activeHref` · `ariaLabel` | ไม่ฝังเมนูไว้ในตัว · ไม่ใช้ `usePathname()` จึงยังเป็น server component ได้ · `aria-current="page"` · ป้ายตัวเลขมี `sr-only` อธิบาย |
| `SpeechBubble` · `DomeSays` · `DomeAvatar` | `speaker` · `tail` · `mood` (greet/cheer/happy) · `live` | `live` ตั้ง `role="status" aria-live="polite"` สำหรับข้อความที่ทยอยมาจาก AI |
| `Chip` · `ChipSlot` | `tone` · `selected` · `draggable` · `dragValue` · `onSelect` | ลากด้วยเมาส์ใช้ไม่ได้กับนิ้วและคีย์บอร์ด ชิปจึงรองรับ **แตะเลือกแล้วแตะช่องปลายทาง** ด้วย — หน้าที่เรียกใช้ต้องรองรับทางนี้เสมอ |
| `Toast` · `ToastViewport` | `tone` · `duration` · `onDismiss` · `action` | error ใช้ `role="alert"` (ขัดจังหวะ) · success/info ใช้ `role="status"` · ลอยอยู่ **บนจอ** เพราะล่างมีแถบเมนูและนิ้วโป้งบัง |
| `Skeleton` · `SkeletonGroup` | `shape` · `lines` · `width` · `height` | ตัว skeleton เป็น `aria-hidden` ทั้งหมด ประกาศ "กำลังโหลด" ครั้งเดียวที่ `SkeletonGroup` · จองพื้นที่ไว้ให้ CLS = 0 |
| `EmptyState` | `title` · `description` · `illustration` · `action` | ภาพส่งเข้ามาจากข้างนอก ไม่ผูกกับภาพใดภาพหนึ่ง |
| `ShopScene` · `stageFromPercent` · `AchievementBadge` | `stage` (1–4) · `decorative` | `stageFromPercent` คุมเกณฑ์ตัดสเตจไว้ที่เดียว (25% / 60% / 100%) |

**ทุกตัวไม่มีข้อมูลตัวอย่างฝังอยู่** — รับค่าผ่าน props ล้วน ข้อมูลสมมติทั้งหมดอยู่ในหน้า `/style-guide` เท่านั้น

## 11. กติกาที่ห้ามละเมิด

1. ห้าม emoji เป็นไอคอน UI — ใช้ SVG จาก `components/ui/icons.tsx` (emoji เรนเดอร์ต่างกันทุกเครื่องและโปรแกรมอ่านหน้าจออ่านชื่อยูนิโค้ดออกมาดิบ ๆ)
2. ห้าม fixed width เป็น px — ใช้ `w-full` + `max-w-*` เสมอ (ตรวจแล้ว: ทั้งระบบไม่มี `w-[Npx]` เลย ค่า `max-w` ที่ใช้มีแค่ 18/20/26/30rem และคู่กับ `w-full` ทุกจุด)
3. ห้ามสีเป็นตัวสื่อความหมายอย่างเดียว — ต้องมีไอคอนหรือข้อความคู่เสมอ
4. ห้ามปุ่ม `primary` เกิน 1 ปุ่มต่อหน้า
5. ห้าม transition เกิน 300ms กับ micro-interaction และห้ามใช้ `scale` กับ hover ที่ทำให้เลย์เอาต์ขยับ
6. ห้ามใช้ `text-note` (13px) กับข้อมูลที่จำเป็นต่อการทำภารกิจ
7. ทุกปุ่มไอคอนต้องมี `aria-label` (บังคับที่ชั้น TypeScript อยู่แล้ว)
8. ทุกหน้าที่มี `BottomNav` ต้องใส่ `pb-nav`

## 1. หลักการ — ยืมกลไก ไม่ใช่ยืมกราฟิก

| Tower of Treasure | วิ่งเก็บตัวอักษรมาประกอบเป็นรหัสผ่าน มีมาตรวัดความแข็งแรง | **A ตั้งชื่อโดเมน** |
| Mindful Mountain | เล็งและส่งข้อมูลให้เข้าช่องผู้รับที่ถูกต้อง ผิดช่องเด้งกลับ | **B เลือกนามสกุลโดเมน** |
| Reality River | ดวลบทสนทนากับตัวละครที่พยายามหลอก ตอบถูกจึงข้ามได้ | **C ทดสอบลูกค้า** |

## 2. สถานี A — โรงทำป้าย (ตั้งชื่อโดเมน)

**กลไกอ้างอิง:** Tower of Treasure

### หน้าจอ
โรงทำป้ายร้าน มีสายพานลำเลียงตัวอักษรและพยางค์วิ่งผ่านจากขวาไปซ้าย ด้านบนเป็นป้ายร้านเปล่าที่ค่อย ๆ สว่างขึ้น

### วิธีเล่น
1. ผู้เล่นแตะเก็บตัวอักษร/พยางค์จากสายพานมาต่อเป็นชื่อโดเมน
2. มีปุ่มลบตัวท้ายและปุ่มล้างทั้งหมด
3. **มีช่องพิมพ์เองด้วยเสมอ** — สายพานคือทางที่สนุก ไม่ใช่ทางบังคับ ผู้เล่นที่พิมพ์เร็วกว่าต้องไม่ถูกลงโทษ

### มาตรวัด "ป้ายสว่าง" 4 ขีด
ตรวจแบบเรียลไทม์ทุกครั้งที่ชื่อเปลี่ยน ขีดติดสว่างทีละอัน

| ขีด | กฎ | ตรวจด้วย |
|:---:|---|---|
| 1 | ความยาว 3–20 ตัวอักษร | โค้ด |
| 2 | ใช้ได้เฉพาะ `a-z` `0-9` และขีดกลาง ห้ามขีดกลางนำหน้าหรือปิดท้าย | โค้ด |
| 3 | อ่านออกเสียงตามได้ ไม่มีตัวอักษรซ้ำติดกันเกิน 2 ตัว | โค้ด |
| 4 | สื่อถึงประเภทธุรกิจที่ผู้เล่นกรอกไว้ตอนต้นเกม | คำสำคัญก่อน ถ้าไม่ชัดค่อยถาม AI แล้วครูยืนยัน |

**3 ใน 4 ข้อตรวจด้วยโค้ดล้วน ไม่ต้องเรียก AI** — เร็วกว่า ไม่มีค่าใช้จ่าย และไม่พังตอนเน็ตหลุด

### ของเสียบนสายพาน
ช่องว่าง, `@ # $ %`, สระและวรรณยุกต์ไทย, จุด
เก็บแล้วป้ายกะพริบแดงพร้อมคำอธิบาย 1 บรรทัดทันที เช่น *"ชื่อโดเมนมีช่องว่างไม่ได้ ลองใช้ขีดกลางแทน"*

### เงื่อนไขผ่าน
มาตรวัดครบ 4 ขีด → กดปุ่ม "ติดป้าย" → กุญแจสถานี B หลุด

### เวลาโดยประมาณ
4 นาที

## 3. สถานี B — สำนักงานจดทะเบียน (เลือกนามสกุลโดเมน)

**กลไกอ้างอิง:** Mindful Mountain

### หน้าจอ
เคาน์เตอร์ 5 ช่อง เรียงกัน แต่ละช่องมีเจ้าหน้าที่และป้ายชื่อนามสกุลโดเมน

### วิธีเล่น
ลากป้ายร้านที่ทำเสร็จจากสถานี A ไปยื่นที่ช่องที่คิดว่าถูกต้อง

| ช่อง | เงื่อนไขโดยสรุป |
|---|---|
| `.com` | ใครก็จดได้ เป็นสากล คนจำง่ายที่สุด ชื่อดี ๆ มักถูกจองหมดแล้ว |
| `.co.th` | ต้องเป็นนิติบุคคลจดทะเบียนในไทย ต้องมีหนังสือรับรอง |
| `.in.th` | บุคคลธรรมดาในไทยจดได้ ใช้บัตรประชาชน |
| `.shop` | สื่อชัดว่าเป็นร้านค้า จดง่าย แต่คนคุ้นน้อยกว่า `.com` |
| `.ไทย` | ชื่อภาษาไทย เหมาะกับลูกค้าคนไทย พิมพ์บนคีย์บอร์ดอังกฤษไม่ได้ |

### เมื่อยื่นผิดช่อง
เจ้าหน้าที่ดีดกลับพร้อมเหตุผลสั้น 1 บรรทัด เช่น
> *".co.th ต้องมีหนังสือรับรองบริษัท ร้านหนูยังไม่ได้จดทะเบียนนิติบุคคล ลองช่องอื่นดู"*

### ตัวช่วยปรับตามระดับผู้เรียน — จุดที่ Personalized มองเห็นเป็นภาพ
| ระดับ | สิ่งที่แสดง |
|:---:|---|
| 1 | ป้ายครบ 3 บรรทัด — ใครจดได้ (`whoCanRegister`) + เหมาะกับใคร (`goodFor`) + ข้อควรระวัง (`watchOut`) |
| 2 | ป้ายบรรทัดเดียว — เห็นแค่ "ใครจดได้" (`whoCanRegister`) ที่เหลือซ่อน |
| 3 | ไม่มีป้ายเลย ต้องจำจากที่ครูสอน (กดปุ่มขอความช่วยเหลือได้) |

ตารางนี้ตรงกับ `hintsForLevel()` ใน `core/tld-rules.ts` ซึ่งเป็นแหล่งความจริง — แก้ระดับตัวช่วยที่โค้ดแล้วต้องแก้ตารางนี้ตาม

นี่คือเหตุผลที่ควรทำสถานี B ให้เสร็จก่อนสถานีอื่น — เป็นสถานีที่โชว์ "ระบบปรับตามคนเรียน" ได้ชัดที่สุดตอนนำเสนอ

### เงื่อนไขผ่าน
ยื่นถูกช่อง + พิมพ์เหตุผลสั้น 1 บรรทัดว่าทำไมนามสกุลนี้เหมาะกับร้าน

### เวลาโดยประมาณ
4 นาที

## 4. สถานี C — ลานทดสอบลูกค้า

**กลไกอ้างอิง:** Reality River

### หน้าจอ
ลานหน้าร้าน มีลูกค้า NPC 2 คนเดินเข้ามาถามหาเว็บของร้าน

### วิธีเล่น
1. ผู้เล่นบอกชื่อโดเมนของตัวเอง (พิมพ์ หรืออัดเสียง)
2. ลูกค้าพิมพ์ตามลงมือถือ แล้วโชว์ผลให้เห็น
3. ถ้าชื่อกำกวม ลูกค้าจะพิมพ์ผิด **ให้เห็นกับตา**

### จุดสอนที่แรงที่สุดของทั้งเกม
ความกำกวมที่ทำให้พิมพ์ผิดบ่อย
- `4` กับ `four` · `2` กับ `to`/`too`
- ขีดกลางที่คนฟังไม่รู้ว่ามี
- ตัวอักษรซ้ำ เช่น `shopp`
- `s` ท้ายคำที่หายไป
- คำที่สะกดได้หลายแบบ เช่น `center` กับ `centre`

### เงื่อนไขผ่าน
ลูกค้าอย่างน้อย 1 ใน 2 คนพิมพ์ชื่อได้ถูกต้อง

### เมื่อไม่ผ่าน
เด้งกลับสถานี A ไปแก้ชื่อ — loop นี้สอนเรื่องการตั้งชื่อได้ดีกว่าให้อ่านกฎ 10 ข้อ

### ทางหลักและทางเสริม
- **ทางหลัก:** ลูกค้าจำลอง AI (คุมได้ ไม่ต้องรอเพื่อน ไม่รวนในคาบ)
- **ทางเสริม:** ให้เพื่อนในห้องสแกน QR แล้วพิมพ์ให้จริง — สนุกกว่าแต่พึ่งไม่ได้

### เวลาโดยประมาณ
5 นาที

## 8. การใช้ AI API (Gemini / Typhoon)

### 8.1 กฎความปลอดภัยข้อเดียวที่ห้ามพลาด

> **ห้ามวาง API key ไว้ในโค้ดฝั่งเบราว์เซอร์เด็ดขาด** ต้องเรียกผ่าน API route ฝั่งเซิร์ฟเวอร์เท่านั้น
> ตัวแปรที่ชื่อขึ้นต้นด้วย `NEXT_PUBLIC_` จะถูกฝังลงไฟล์ที่ผู้ใช้โหลดได้ — **อย่าตั้งชื่อ key ว่า `NEXT_PUBLIC_GEMINI_API_KEY`**
> ถ้าเผลอ commit key ขึ้น git ให้ถือว่า key นั้นรั่วแล้ว ต้องยกเลิกและออกใหม่ทันที

ตั้งค่าใน `.env.local` (อย่า commit ไฟล์นี้):

```
GEMINI_API_KEY=...
TYPHOON_API_KEY=...
```

```ts
import { NextResponse } from 'next/server'
import { ruleBasedHint } from '@/core/hints'

const TYPHOON_URL = 'https://api.opentyphoon.ai/v1/chat/completions'
const MODEL = 'typhoon-v2.5-30b-a3b-instruct'

export async function POST(req: Request) {
  const { station, draft, business, level } = await req.json()

  // ทางสำรองแบบกฎ เตรียมไว้ก่อนเสมอ
  const fallback = ruleBasedHint(station, draft, level)

  try {
    const res = await fetch(TYPHOON_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${process.env.TYPHOON_API_KEY}`,
      },
      body: JSON.stringify({
        model: MODEL,
        max_tokens: 300,
        temperature: 0.4,
        messages: [
          { role: 'system', content: HINT_SYSTEM_PROMPT },
          {
            role: 'user',
            content: `ร้าน: ${business}\nชื่อที่คิดไว้: ${draft}\nระดับตัวช่วย: ${level}`,
          },
        ],
      }),
      signal: AbortSignal.timeout(5000),
    })

    if (!res.ok) throw new Error(String(res.status))
    const data = await res.json()
    const text = data.choices?.[0]?.message?.content
    return NextResponse.json({ hint: text ?? fallback, source: 'ai' })
  } catch {
    return NextResponse.json({ hint: fallback, source: 'rule' })
  }
}
```

**จุดสำคัญ 4 ข้อ**
1. `AbortSignal.timeout(5000)` — เน็ตโรงเรียนช้าได้ ต้องไม่ให้เด็กรอค้าง
2. `ruleBasedHint()` เตรียมไว้ก่อนเสมอ ถ้า AI ล้มก็ยังมีคำใบ้ให้
3. รูปแบบ request เข้ากันได้กับ OpenAI จะเปลี่ยนไปใช้ SDK ของ OpenAI ที่ชี้ `baseURL` มาที่ Typhoon ก็ได้
4. **นับจำนวนเรียกต่อคน** ฝั่งเซิร์ฟเวอร์ เพดาน 200 ครั้ง/นาที เป็นของทั้งห้องรวมกัน ไม่ใช่ของแต่ละคน

### 8.5 API route สำหรับประเมินเหตุผล (Gemini + structured output)

ให้ AI ตอบเป็น JSON ตามสคีมาที่กำหนด ไม่ต้องมานั่งแกะข้อความ

`app/api/assess/route.ts`

```ts
import { GoogleGenAI, Type } from '@google/genai'

const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY })
const MODEL = 'gemini-3.5-flash-lite'   // ปรับตามโควตาฟรีที่บัญชีได้จริง

const RUBRIC_SCHEMA = {
  type: Type.OBJECT,
  properties: {
    relevance: { type: Type.INTEGER },   // เหตุผลตรงกับร้านหรือไม่ 1-4
    accuracy:  { type: Type.INTEGER },   // ข้อมูลนามสกุลโดเมนถูกต้องหรือไม่ 1-4
    clarity:   { type: Type.INTEGER },   // อธิบายเข้าใจง่ายหรือไม่ 1-4
    feedback:  { type: Type.STRING },    // คำแนะนำสั้นถึงนักเรียน ภาษาไทย
    needsTeacherReview: { type: Type.BOOLEAN },
  },
  required: ['relevance', 'accuracy', 'clarity', 'feedback', 'needsTeacherReview'],
}

const result = await ai.models.generateContent({
  model: MODEL,
  contents: studentAnswer,
  config: {
    systemInstruction: RUBRIC_SYSTEM_PROMPT,
    responseMimeType: 'application/json',
    responseSchema: RUBRIC_SCHEMA,
  },
})

const scores = JSON.parse(result.text)
```

**หมายเหตุทางเทคนิค**
- `responseMimeType: 'application/json'` + `responseSchema` คือวิธีบังคับรูปแบบผลลัพธ์ของ Gemini
- ตรวจค่าที่ได้ด้วย `zod` อีกชั้นก่อนเขียนลงฐานข้อมูลเสมอ อย่าเชื่อ AI ตรง ๆ
- ถ้าเรียกไม่สำเร็จ ให้ตั้ง `needsTeacherReview = true` แล้วส่งเข้าคิวให้ครูตรวจเอง **อย่าให้ระบบค้าง**
- **คะแนนจาก AI เป็นเพียงข้อเสนอ ครูเป็นคนยืนยันเสมอ** — ตรงนี้คือคำตอบที่ต้องเตรียมไว้ตอบกรรมการ
- ถ้าโควตาฟรีของ Gemini ไม่พอ ย้ายงานนี้ไป Typhoon แล้วสั่งใน system prompt ให้ตอบเป็น JSON อย่างเดียว พร้อมตรวจด้วย `zod` (ไม่มีการันตีรูปแบบระดับ API แต่ใช้ได้)

### 8.6 ลูกค้าจำลอง AI (สถานี C) — ข้อควรระวัง

เป็นช่องที่นักเรียนพิมพ์อะไรก็ได้ ต้องกัน 3 อย่าง
1. **จำกัดความยาว input** ฝั่งเซิร์ฟเวอร์ (เช่น 200 ตัวอักษร)
2. **จำกัดจำนวนครั้งต่อคน** ต่อคาบ กันทั้งการเล่นนอกเรื่องและค่าใช้จ่ายบานปลาย
3. **ระบุขอบเขตใน system prompt** ว่าให้ทำตัวเป็นลูกค้าที่พยายามพิมพ์ชื่อเว็บตามที่ได้ยินเท่านั้น ไม่ตอบเรื่องอื่น

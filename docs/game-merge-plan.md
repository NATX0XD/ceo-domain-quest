## 1. ผนวกได้ไหม — ได้ และเข้ากันดีกว่าที่คิด

flow ที่ทีมออกแบบไว้มีโครงเหมือนเกม Interland อยู่แล้วโดยไม่รู้ตัว

| Interland | flow ภารกิจโดเมนของร้านฉัน |
|---|---|
| เกาะ 4 เกาะ แต่ละเกาะ 1 หัวข้อ | สถานี A / B / C แต่ละสถานี 1 ทักษะ |
| ด่านล็อก เล่นผ่านแล้วปลด | กุญแจล็อกหน้าสถานี ผ่านเกณฑ์จึงไปต่อ |
| ตอบผิดแล้วอธิบายเหตุผลทันที | AI ถามนำ / ถามกลับ เมื่อไม่ผ่านด่านตรวจ |
| จบเกมได้ใบประกาศนียบัตร (jsPDF) | พิธีเปิดร้าน (ทุกคน) + **ใบประกาศเปิดร้านเฉพาะคนที่ครูยืนยันแล้วได้ระดับ 3 ครบ 4 ด้าน** — ต่างจากต้นแบบตรงนี้โดยตั้งใจ (มติ T40) |
| รอบเล่นสั้น จบใน 5–10 นาที | สถานีละไม่เกิน 7 นาที |
| มีคู่มือครูแจกคู่เกม | มีแผงครูอยู่ในระบบเลย (ดีกว่า Interland) |

**สิ่งที่ flow นี้มีแต่ Interland ไม่มี:** โปรไฟล์ผู้เรียน, การจัดเส้นทางรายคน, แผงครูสด, การประเมินด้วยรูบริก, ข้อมูลย้อนกลับไปปรับการสอน
พูดง่าย ๆ คือ **"Interland + สมองที่จำผู้เรียนได้ + ครูที่เห็นทุกอย่าง"** — อันนี้คือประโยคที่ใช้ขายตอนนำเสนอและตอนแข่งได้เลย

## 2. แปลง flow เป็นโลกของเกม

ใช้อุปมา "สร้างร้าน" ที่ทีมวางไว้แล้ว ทำเป็นแผนที่เมืองเล็ก ๆ เดินไปตามสถานี

```
                    [ ห้องสมุดทบทวน ]        <- เปิดได้ตลอดเวลา ไม่ล็อก
                            |
[ จุดเริ่ม ] -- [ A โรงทำป้าย ] --🔒-- [ B สำนักงานจดทะเบียน ] --🔒-- [ C ลานทดสอบลูกค้า ] --🔒-- [ เวทีเปิดร้าน ]
   รับโจทย์        ตั้งชื่อโดเมน            เลือกนามสกุล              ทดสอบความเข้าใจ           ส่งงาน + ใบประกาศ
```

**สภาพร้านเปลี่ยนตามความคืบหน้า** (จากภาพที่ทีมทำไว้): ที่ดินให้เช่า → ฐานราก → ก่ออิฐ → ติดป้าย + ใบจดทะเบียน → Grand Opening
ตัวร้านคือแถบความคืบหน้าที่มองเห็นได้ ไม่ต้องมี progress bar แยก

**สิ่งที่ทำให้รู้สึกเป็นเกม ไม่ใช่แบบฟอร์ม**
- กล้องเลื่อนตามตัวละครเวลาเปลี่ยนสถานี ไม่ใช่โหลดหน้าใหม่
- กุญแจหน้าสถานีหลุดออกมีเสียงและอนิเมชันตอนผ่านเกณฑ์
- ลูกค้า NPC เดินเข้าร้านเพิ่มขึ้นเมื่อผ่านสถานี
- ตอนเปิดร้านมีคนมาต่อแถว ริบบิ้น กระดาษโปรย
- AI ผู้ช่วยเป็นตัวละครในเกม (เจ้าของร้านข้าง ๆ ที่มาให้คำแนะนำ) ไม่ใช่กล่องแชทลอย ๆ

## 3. สถาปัตยกรรม — แยกสมองออกจากภาพ

นี่คือหัวใจของแผนนี้ ถ้าทำถูกจะไม่มีทางส่งงานไม่ทัน

```
┌──────────────────────────────────────────────────────┐
│  ชั้นภาพ (Presentation)                              │
│  โลกเกม 2.5D / 3D  ←→  โหมดสำรอง: การ์ดธรรมดา        │
│  สลับได้ด้วยสวิตช์ตัวเดียว                            │
└───────────────────────┬──────────────────────────────┘
                        │ อ่าน state, ส่ง action
┌───────────────────────┴──────────────────────────────┐
│  ชั้นตรรกะ (Core) — ไม่มีโค้ดวาดภาพเลย               │
│  • state machine 5 สถานี                             │
│  • กฎตรวจชื่อโดเมน 4 ข้อ (ฟังก์ชันล้วน)              │
│  • ตัวเลือกนามสกุลโดเมน + เหตุผล                      │
│  • ตัวจัดระดับตัวช่วย 1/2/3                          │
│  • รูบริก + การให้คะแนน                              │
└───────────────────────┬──────────────────────────────┘
                        │
┌───────────────────────┴──────────────────────────────┐
│  ชั้นข้อมูลและ AI                                     │
│  Supabase (โปรไฟล์ ความคืบหน้า แผงครู)               │
│  Claude API เรียกผ่าน API route ฝั่งเซิร์ฟเวอร์เท่านั้น │
└──────────────────────────────────────────────────────┘
```

**กติกาที่ต้องถือให้มั่น**
1. ชั้นตรรกะต้อง**ทดสอบได้โดยไม่ต้องเปิดเบราว์เซอร์** เขียนเป็น TypeScript ล้วน ไม่ import อะไรจาก Phaser หรือ Three.js
2. ชั้นภาพเปลี่ยนได้โดยไม่แตะตรรกะ — ถ้า 3D ไม่ทัน สลับเป็นโหมดการ์ดแล้วส่งงานได้ทันที
3. ทุกที่ที่เรียก AI ต้องมีทางสำรองแบบกฎ ถ้าไม่ตอบใน 5 วินาที ใช้คำใบ้สำเร็จรูป

## 4. เลือกเทคโนโลยีชั้นภาพ

| ทาง | ใช้อะไร | เวลาที่ต้องใช้ | ความเสี่ยง | หน้าตา |
|---|---|:---:|:---:|---|
| **A. การ์ด 2D** | HTML + Tailwind + Framer Motion | 2 วัน | ต่ำมาก | เรียบร้อย แต่ไม่เหมือนเกม |
| **B. ฉาก 2.5D** (แนะนำ) | ภาพ isometric PNG/SVG ซ้อนชั้น + Framer Motion + Lottie | 4–5 วัน | ต่ำ | เหมือนภาพที่ทีมทำไว้มาก |
| **C. 3D จริง** | React Three Fiber + drei + โมเดล `.glb` | 10+ วัน | สูง | ใกล้ Interland ที่สุด |

**ข้อเสนอ: ทำ A ให้เสร็จก่อน แล้วอัปเป็น B** — เพราะชั้นตรรกะเหมือนกัน เปลี่ยนแค่ชั้นภาพ
C เก็บไว้ทำเฉพาะ "ฉากเปิดร้าน" ฉากเดียวถ้าเหลือเวลา ฉากเดียวที่เป็น 3D ก็พอสร้างความว้าวตอนนำเสนอแล้ว โดยไม่ต้องเสี่ยงทั้งเกม

**ทำไมไม่ใช้ Phaser** — flow นี้มีฟอร์ม ปุ่ม แชท ตาราง และแดชบอร์ดครูเยอะมาก ซึ่งเป็นงานของ HTML ไม่ใช่งานของ canvas ถ้าใช้ Phaser จะต้องเขียน UI ซ้ำทั้งหมดบน canvas เสียเวลาเปล่า

## 5. Stack สรุป

```
Next.js (App Router) + TypeScript + Tailwind      เว็บ + หน้าครู + API route
Framer Motion + Lottie                            อนิเมชันฉากและตัวละคร
@react-three/fiber + drei                         เฉพาะฉากเปิดร้าน (ทำทีหลัง ถ้ามีเวลา)
Howler.js                                         เสียงประกอบ
Supabase (Postgres + Realtime)                    โปรไฟล์ผู้เรียน ความคืบหน้า แผงครู
Claude API (เรียกจาก API route เท่านั้น)           ผู้ช่วยถามนำ + ประเมินเบื้องต้น
jsPDF                                             ใบประกาศเปิดร้าน สร้างในเบราว์เซอร์
Vercel                                            deploy ด้วย git push ได้โดเมนสั้นทำ QR
```

**ห้ามเด็ดขาด:** วาง API key ของ Claude ไว้ในโค้ดฝั่งเบราว์เซอร์ ต้องเรียกผ่าน API route ฝั่งเซิร์ฟเวอร์เสมอ

## 7. ไทม์ไลน์ถึงวันส่ง

เหลือ **8 วัน** ถึงกำหนดส่งความก้าวหน้า 80% (7 ตุลาคม 2569)

| วัน | งาน | ผลที่ต้องได้ |
|---|---|---|
| 29–30 ก.ย. | ตั้งโปรเจกต์ Next.js + Supabase, เขียน `core/` ทั้งหมด พร้อมเทสต์ | กฎตรวจชื่อโดเมนทำงานถูก ทดสอบผ่านโดยไม่ต้องเปิดเบราว์เซอร์ |
| 1 ต.ค. | เข้าระบบด้วยรหัสห้อง + ชื่อเล่น, คำถามก่อนเรียน, สร้างโปรไฟล์ | นักเรียนเข้าเกมและได้ระดับตัวช่วยแล้ว |
| 2–3 ต.ค. | สถานี A และ B โหมดการ์ด + คำใบ้แบบกฎ | เล่นจนจบสถานี B ได้จริง |
| 4 ต.ค. | หน้าสรุปผล + ใบประกาศ jsPDF + แผงครูแบบอ่านอย่างเดียว | เดโมได้ตั้งแต่เข้าเกมจนได้ใบประกาศ |
| 5–6 ต.ค. | อัปชั้นภาพเป็นโหมดฉาก 2.5D, ใส่เสียง, ต่อ Claude API สำหรับคำใบ้ | หน้าตาเป็นเกมจริง |
| 7 ต.ค. | เก็บงาน อัดคลิปเดโม เขียนรายงานความก้าวหน้า **ส่ง 80%** | ส่งตามฟอร์ม |
| 8–20 ต.ค. | สถานี C, AI ประเมินเบื้องต้น, แม่แบบ T1–T6 ครบ, ทดลองใช้กับคนจริง | ระบบครบตาม flow |
| 21–31 ต.ค. | แก้จากผลทดลอง, ฉากเปิดร้าน 3D (ถ้าทัน), แผนการสอน, คู่มือ, สไลด์ | เอกสารครบ 4 ชิ้นตามที่อาจารย์กำหนด |
| 1 พ.ย. | **ส่งงาน** แผนการสอน + คู่มือ + สไลด์ + สื่อ | ทุกคนในกลุ่มส่ง |
| 2–3 พ.ย. | ซ้อมนำเสนอ 15 นาที + ถาม-ตอบ 5 นาที | เตรียมแผนสำรองตอนเน็ตล่ม |

**เส้นตายที่ห้ามพลาด:** สิ้นวัน 4 ตุลาคม ต้องเดโมได้ครบเส้นทางแล้ว แม้หน้าตายังเป็นการ์ดธรรมดา
ถ้าถึงวันนั้นยังเดโมไม่ได้ ให้ตัดสถานี C และโหมดฉากทิ้งทันที อย่าดันต่อ

## 8. แผนสำรองตอนนำเสนอ

- อัดคลิปเดโมเต็มรอบไว้ล่วงหน้า เปิดแทนได้ทันทีถ้าเน็ตล่ม
- เตรียมโหมดออฟไลน์ที่ใช้ข้อมูลตัวอย่างในเครื่อง ไม่ต้องต่อ Supabase
- ให้ผู้ฟังสแกน QR เล่นเองระหว่างนำเสนอ — จุดนี้ได้คะแนน "การสื่อสารแนวคิด" ชัดที่สุด แต่ต้องทดสอบกับคน 20 คนพร้อมกันก่อน
- เตรียมคำตอบคำถามที่กรรมการถามแน่ ๆ: AI ตัดสินผิดแล้วทำอย่างไร (ตอบ: ครูยืนยันคะแนนเสมอ), ข้อมูลนักเรียนเก็บอะไรบ้าง (ตอบ: ชื่อเล่นกับคำตอบเท่านั้น ไม่มีข้อมูลส่วนบุคคล)
